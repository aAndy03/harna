# The plugin interface

A plugin is a versioned data pack for one framework or ecosystem, such as
gpui-kit 0.8.0 or Tauri. It carries the framework's rules, vocabulary and
public API as data, so harna's core keeps no framework knowledge (rule
`tools-not-prescriptions`). This page is the specification of **plugin
interface 1**, stable since harna 1.0.

## What a plugin is not

A plugin holds no code. Its rules bind harna's generic checks with
arguments; nothing in a pack is executed by `validate`, the hooks or
`preflight` (non-goal `no-plugin-code-in-the-gate`). A proof that needs
code to run belongs in a registered command that CI runs.

## Where packs come from

`harna plugin add <spec>` installs a pack, where `<spec>` is:

- the name of a pack shipped inside harna (`harna plugin list` shows them);
- the name of a pack under `~/.harna/plugins/<name>/`;
- a path to a pack folder.

The pack is copied to `.harna/plugins/<name>/` and committed with the code.
The repository then reads it offline, and a review sees exactly what
applies. `harna plugin remove <name>` uninstalls it.

## Layout

```
<name>/
  plugin.toml   who the pack is, what it mirrors (required)
  rules.toml    the framework's rules (optional)
  terms.toml    the framework's vocabulary (optional)
  api.toml      the mirrored crate's public surface (optional, generated)
```

The folder's name and `plugin.toml`'s `name` must match. A name is
lowercase letters, digits, `-` and `_`.

## `plugin.toml`

| Key | Required | Meaning |
|---|---|---|
| `name` | yes | The pack's name. |
| `interface` | no | The plugin interface the pack is written for. Absent means 1. |
| `description` | no | One line for `harna plugin list`. |
| `version` | no | The pack's own version, for example `0.8.0-8`. |
| `sources` | no | Where the knowledge comes from: docs and guides, for the reader. |
| `[mirrors]` | no | Upstream packages the pack keeps parity with: `gpui-kit = "0.8.0"`. `harna doctor` warns when a Cargo package listed here drifts from `Cargo.lock`. |
| `[capabilities]` | no | Named sets of framework tokens one container may own, such as `raw-input = ["on_mouse_down(", …]`. The manifest names one as `<plugin>:<capability>` in a container's `owns`. Anyone else calling those tokens is reported. |
| `[[bridges]]` | no | Cross-language calls: `name`, a `rust` regex for the marker before an exposed `fn`, and a `ts` regex for the call, with `NAME` standing for the function. Each call becomes an edge in the code map. |

## `rules.toml` and `terms.toml`

Both use the same format as the project's own files (see
[FORMAT.md](FORMAT.md)), including `schema_version`. A rule's id is used
as `<plugin>/<id>`, so it never collides with the project's rules. The
project can override one by adopting it (`harna add-rule` with the
namespaced id) or switch one off by deprecating it.

## `api.toml`

The public surface of the crate the pack mirrors, generated by
`harna plugin api` from that release's source: `crate`, `version`, and
`[[modules]]` with a `path`, its public `items`, and `open = true` when a
glob re-export lives there. The `api-parity` check reads it to name an
invented module or item. Regenerate it with each upgrade of the mirrored
crate.

## Stability

- **Interface 1 is stable.** Every key above keeps its meaning, and a
  pack written for interface 1 reads with every later harna.
- **A key that changes what a pack enforces is a new interface.** Adding
  one, removing a key, or changing a key's meaning makes interface 2. An
  older harna ignores keys it does not know, so a pack that needs a new key
  must declare the interface that has it. harna keeps reading packs
  written for 1.
- **Interfaces start at 1.** `interface = 0` is refused.
- **Newer packs are refused, not misread.** A pack whose `interface` (or
  whose `rules.toml` / `terms.toml` `schema_version`) is newer than this
  harna speaks is refused by `harna plugin add` before anything is copied,
  and fails to load with a message to upgrade harna. `harna doctor` names
  it. A harna older than 1.0 does not know `interface` and ignores it.
- **Tested.** `crates/harna-core/tests/formats.rs` reads every shipped pack
  and a pack from a future interface.
