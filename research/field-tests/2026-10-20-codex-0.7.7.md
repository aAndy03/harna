## Step 4 - BREAKING change
### 4a. sim1: `canonicalize_existing_preserving_symlinks(path)` becomes `(path, strict: bool)` in codex_utils_absolute_path
Real callers by grep: 3 crates, 5 files (cli/tests/plugin_cli.rs and marketplace_remove.rs, exec/src/lib.rs, tui/src/lib.rs). All use the root-form import `use codex_utils_absolute_path::canonicalize_existing_preserving_symlinks;`.

`harna validate` WITHOUT re-running scan: no contract finding and no warning that the digest is stale (FINDING D). After `harna scan`:
```
[!contract] .harna/contracts/codex_utils_absolute_path.toml — breaking change to contract `codex_utils_absolute_path` v1.0.0: `canonicalize_existing_preserving_symlinks` changed: `pub fn ...(path: &Path) -> std::io::Result<PathBuf> {` -> `pub fn ...(path: &Path, strict: bool) -> std::io::Result<PathBuf> {`
  fix: keep it compatible, or accept the break: harna contract freeze codex_utils_absolute_path --version 2.0.0 (and tell its importers: harna dependents)
```
Verdict: correct, error severity, shows old/new signature and the fix; also appears under `validate --changed`. Gaps: needs manual scan first; the message points at the contract toml, not the source file:line; the suggested `harna dependents` is useless here (see below).

`harna parity open sim1`:
```
parity `sim1` gen1: 1 target(s): 0 open — nothing owed; 1 origin (your change), 0 auto-resolved, 0 hand-resolved
```
MISSES: 3 of 3 real caller crates (5 files) -> 0 targets. False targets: 0.
`harna affected` (working tree and commit range): `containers changed: codex_utils_absolute_path / containers importing them: none / run: cargo test -p codex-utils-absolute-path`. MISS 3/3.

ROOT CAUSE (FINDING E, most important bug): cross-crate imports in the root form `use codex_x::Item;` create no edge to that crate's `lib.rs`. `harna dependents codex-rs/utils/absolute-path/src/lib.rs` prints "nothing imports ... directly", same for `protocol/src/lib.rs`, `core/src/lib.rs`, `codex-api/src/lib.rs`, although the deps ARE in the digest (`"codex_utils_absolute_path::canonicalize_existing_preserving_symlinks"` in exec's shard). Edges form only for submodule-form imports (`use codex_protocol::permissions::X`; dependents of `protocol/src/permissions.rs` = 56). Root-form is the norm for items defined or re-exported in lib.rs, so parity, `dependents`, `affected` and the deprecation-window fix hint are blind exactly there. Scale: `harna affected` lists 14 importers of codex_protocol while 77 Cargo.toml files depend on codex-protocol.
Likely fix: map the first path segment via Cargo `[package] name` (`-` to `_`) to the crate's lib.rs, follow `pub use` re-exports to the defining module, and for `affected` union the Cargo dependency graph.

## Bugs, false results, confusing messages (collected)
1. E (major, false negative): root-form crate imports create no edge to lib.rs, so parity, affected and dependents are blind (map crate name via Cargo `[package] name`, follow `pub use`).
2. F (false negative): contract freezes only the first signature line.
3. D: validate/parity/affected give no warning when the digest is stale against disk.
4. G: freeze accepts a breaking surface under a minor version.
5. A: render silently skips a hand-written CODEOWNERS; `render --check` reports current.
6. B: owners/CODEOWNERS cover only `src/`; layer owner not a fallback.
7. `validate --changed` is as slow and as loud as full validate; plain `adopt` emits placeholder layer/container names (`adopted`, `unnamed`).
8. parity headline counts 55 auto-resolved importers as targets.
9. `harna parity status` does not exist (it is `parity show`, which takes no id): hard to guess.
10. H: `#[deprecated]` without `since` invisible.
11. `deprecations --root codex-rs` error text is a raw OS path error.
12. Missing tools: `owners --base <ref>`; `affected` transitive / Cargo-graph union; owners of affected importers in `affected --json`; a project-version override for `deprecations`; CODEOWNERS import from an existing file; `contract diff <container>`; persisted adopt/scan excludes.

## Suggestions
1. Fix crate-root edge resolution first (E); add a regression fixture: crate A `pub fn f` in lib.rs, crate B `use a::f;`.
2. Freeze whole signatures (join continuation lines up to `{`/`;`, include where clauses; hash trait/struct bodies).
3. Make validate/parity/affected rescan incrementally (about 3s here) or warn "digest older than N changed files".
4. Refuse freezing a non-superset as a minor/patch.
5. Render: report what it skipped; emit a single layer-owner line; resolve owners at the Cargo crate root.
6. Exclude `.harna/**`, generated views and aside files from changed/unowned listings.
7. Parity: keep `auto` rows out of the headline count.
8. Offer a project-version override for monorepos with a placeholder version.
