# Field test: typescript-app brief, harna 0.9.1 (2026-10-20)

Tester: fresh agent, Windows 11 + Git Bash. Project: `scratchpad/ft092-ts` (deleted at the end).

## What I built

A small ledger app:

- `package.json` with `workspaces: ["packages/*"]`, and `packages/shared` (`@app/shared`: `Id`, `newId`).
- `tsconfig.json` with `paths`: `@domain/*`, `@ui/*`, `@client/*`.
- `src/domain/` holds `money.ts`, `account.ts` (imports `@app/shared`), `internal.ts` (private) and the `index.ts` barrel.
- `src/client/` holds `events.ts` (TS mirror: `PostingCreated extends BaseEvent`, `PostingVoided`) and `http.ts` (axios).
- `src/ui/AccountView.tsx` imports `@domain/account` and `@client/http`.
- `server/` is a zero-dependency Rust crate (`cargo build --offline` OK). It declares `PostingCreated {id, at, account, amount_cents}` and `PostingVoided`.
- `schemas/posting-voided.schema.json` is a JSON Schema with `properties`.

harna structure:

- Layers: `base(shared)`, `core(domain) -> base`, `io(client) -> base,core`, `ui(ui) -> base,core,io`, `backend(server)`.
- `client` has `--gateway npm:axios`. `domain` has `--provides Money,Account,add,deposit`.
- Services: `api [server] owns db:ledger` and `web [client, ui, domain]`. `shared` belongs to no service.
- Corridor `postings` (event, api -> web) carries `PostingCreated=server/src/lib.rs::PostingCreated` and `PostingVoided=schemas/posting-voided.schema.json`.

## Break list

All tests ran with `harna scan && harna validate` unless stated otherwise.

### 1. Domain imports the UI: CAUGHT

- **Relative path** (`src/domain/leak.ts`: `import { AccountView } from "../ui/AccountView"`):
  `[!layer-boundary] src/domain/leak.ts:1 — imports `src/ui/AccountView.tsx` (src/ui in layer ui), not in core's allowed set`
- **Through the alias** (`@ui/AccountView`): the same error.
- **Also caught:**
  - `paths` declared in an `extends`-ed `tsconfig.base.json`
  - a bare alias `"@view": ["src/ui/AccountView.tsx"]`
  - a `.mjs` file
- **Caveat:** without `harna scan` first, `validate` prints `warning: the map is stale for 1 changed file(s) ... run harna scan first` and then **PASS, exit 0**. A stale map should not pass.

### 2. A UI file imports axios while a gateway owns it: CAUGHT

`[!gateway-ownership] src/ui/raw.ts:1 — imports package `axios`, which only `src/client` may (gateway npm:axios)`

Caught for every import form tried:

- default import
- `axios/dist/axios` subpath
- `require("axios")`
- dynamic `import("axios")`
- `import type`
- `export { default as ax } from "axios"`

**MISSED (expected by analogy with `crate:`):** `packages/shared/package.json` declaring `"dependencies": {"axios": ...}` passes. The `crate:` gateway checks who *depends* on the crate; `npm:` does not check who depends on the package.

### 3. A file imports another container's private module: CAUGHT

`[!declared-surface] src/ui/priv.ts:1 — imports `secretRounding` from container `domain`, which provides only Money, Account, add, deposit`

- **Caught:** named, relative, namespace (`*`), default, aliased (`as sr`), and a barrel-dir import (`"../domain"`).
- **MISSED:** a side-effect import `import "@domain/internal";` passes.
- **FALSE POSITIVE:** `import * as D from "@domain/index"` errors with `imports `*` from container `domain``. Every name that barrel exports is in `provides`, so this is the container's public face.

### 4. The TS mirror renames, adds and drops a field: CAUGHT

- **Rename:** `[!corridor-shape] src/client/events.ts — service `web`'s `PostingCreated` differs from corridor `postings`'s shape (server/src/lib.rs): missing [amount_cents], extra [amount]`
- **Add:** `missing [], extra [memo]`. An optional `memo?` is flagged too.
- **Drop:** `missing [account], extra []`
- **Drop a field held in the base interface:** `missing [at]`
- The match of `amountCents` against `amount_cents` works, because case and `_` are ignored.
- Cosmetic: empty `missing []` and `extra []` lists are printed.

### 5. The mirror `extends` a base interface: PARTIAL (false positives)

- **No false positive** for a base in the same file, and for a multi-level `A -> B -> PostingCreated` chain in the same file.
- **FALSE POSITIVE when the base is imported from another file:**
  - `import { BaseEvent } from "./base"; export interface PostingCreated extends BaseEvent {...}` gives `[!corridor-shape] ... missing [id, at], extra []`.
  - The same happens with a base from the workspace package (`import { Envelope } from "@app/shared"`).
  - This is the common real layout: the base lives in its own file.
- **FALSE POSITIVE for an intersection alias:** `type PostingCreated = BaseEvent & { account: string; amountCents: number }` gives `missing [id, at]`.

### 6. A class mirror with constructor parameter properties: CAUGHT (fields read)

- **Read correctly:**
  - `constructor(public id: string, public at: number, public readonly account: string, private amountCents: number)`: PASS
  - dropping one parameter property: `missing [amount_cents]`
  - plain (non-property) constructor parameters are ignored
  - `static` fields are ignored
  - annotated fields (`id: string = ""`, `id!: string`) are read
  - methods are ignored
- **FALSE POSITIVE:** class fields without a type annotation (`at = 0;`, `account = "";`) are not read.
  - `class PostingCreated { at = 0; constructor(public id: string, public account: string, readonly amountCents: number) {} }` gives `missing [at]`.
  - Every untyped-initializer class gives `missing [id, at, account, amount_cents]`.
- **FALSE POSITIVE:** quoted interface keys. `{ "id": string; ... }` gives `missing [id]`.

### 7. A JSON Schema shape with `properties`: CAUGHT

Both ends are compared against the schema:

- The TS side drops `reason`: `[!corridor-shape] src/client/events.ts — service `web`'s `PostingVoided` differs from corridor `postings`'s shape (schemas/posting-voided.schema.json): missing [reason], extra []`
- The Rust side renames `posting_id`: `[!corridor-shape] server/src/lib.rs — service `api`'s `PostingVoided` differs ...: missing [postingId], extra [posting_ref]`
- The schema adds `by`: both ends report `missing [by]`.
- Nested object `properties` and `definitions` do not leak in.
- A deleted schema gives `[!service-coherence] ... shape `schemas/posting-voided.schema.json` is not a file`.
- **FALSE POSITIVE:** a schema that gets fields through `allOf: [{"$ref": "#/$defs/Base"}]` is not resolved, so both ends report `extra [at]`.

### 8. The client imports the server service's code directly: CAUGHT

- **Rust source:** `[!service-talk] src/client/direct.ts — service `web` imports `server/src/lib.rs`, code service `api` runs (`file:server/src/lib.rs`) — services talk through corridors`
  - fix: `server/src/lib.rs holds corridor postings's message shape inside service api: move the shape to a shared container both link`
  - This is an excellent, context-aware fix line.
- **A `.ts` file in the server container:** caught too, with `fix: send it through postings instead`.

### 9. A deleted file that others imported: CAUGHT

`git rm src/domain/money.ts` (also after committing it on a branch), then `harna affected --base master`:

```
1 changed file(s)
test everything:
  src/domain/money.ts is gone: its importers are not in the new map
containers changed: domain
containers importing them: none
services to redeploy: web
TS/JS folders to test: src/domain
```

JSON: `"everything": true, "reasons": ["src/domain/money.ts is gone: ..."]`.

Weak point: the reason does not name the importers, although the base map knows them (`account.ts`, `index.ts`). "containers importing them: none" is misleading while `ui` imports `domain`.

**Tally: 8 CAUGHT, 1 PARTIAL (item 5: cross-file `extends` and intersection give false positives).** The brief's expectations hold for the exact shapes named. Ordinary variations produce false-positive errors (items 3, 5, 6, 7).

### What a fresh engineer would expect, but harna MISSES

- **TS import cycles**, at the file level (`a.ts <-> money.ts` in one container) and the container level (`domain <-> rates`, same layer). They pass even with `harna add-rule --id acyclic --check no-cycles`, whose output is `no violations found`.
- **`#[serde(rename = "acct")]` is ignored.** The Rust field `account` (wire name `acct`) matches TS `account`, so the result is a silent wrong PASS.
- **`#[serde(skip)]` is ignored**, which gives a false positive: `missing [cache]`.
- **Field types are not compared.** TS `at: string` against Rust `at: u64` passes. That is probably by design, but worth saying in the docs.
- **The npm gateway** does not check `package.json` dependencies (see item 2).
- **Side-effect imports** of a private module are not checked (see item 3).
- **Transitive impact:**
  - `dependents src/domain/money.ts` shows `0 knock-on (ring 2)` although `account.ts -> AccountView.tsx` imports it transitively.
  - `affected` with `packages/shared` changed lists `domain` only, not `ui` (which imports `domain`).

## Bugs (exact repros)

Setup for all repros: the project above with services and corridor, scanned and committed.

### B1 (high): `validate --changed` is wrong for TS-only changes and for a clean tree

```
git status        # clean (or only .ts changed)
harna validate --changed
```

Output:

```
no changed .rs files — running manifest-level checks only
[?corridor-shape] ... service `api` is on corridor `postings` but its code never names `PostingCreated` ...
[?corridor-shape] ... service `web` ... never names `PostingCreated` ...
[!service-coherence] .harna/services.toml — corridor `postings`: message `PostingCreated` names `server/src/lib.rs`, which the map does not hold
verdict: BLOCKED
```

- The partial map is built from changed `.rs` files only, so the corridor checks see a map missing `server/src/lib.rs` and every TS mirror.
- The result is a false **ERROR** that blocks the commit.
- The message "no changed .rs files" ignores `.ts` files. A `.ts` layer violation *is* reported after a scan, so the message is also wrong.
- With one `.rs` file changed, the false error disappears, but the `web` corridor-shape info remains.
- This is the command AGENTS.md tells agents to run after every burst.

### B2 (high): corridor-shape false positive when an interface extends a base declared in another file

```
printf 'export interface BaseEvent { id: string; at: number }\n' > src/client/base.ts
printf 'import { BaseEvent } from "./base";\nexport interface PostingCreated extends BaseEvent { account: string; amountCents: number }\n' > src/client/events.ts
harna scan && harna validate
# [!corridor-shape] src/client/events.ts — ... missing [id, at], extra []
```

The same happens with the base imported from `@app/shared`, and with `type PostingCreated = BaseEvent & {...}`.

### B3 (high): `container surface` on TS proposes a surface that breaks valid code

```
harna container surface domain
# draft: add, deposit, secretRounding
harna container surface domain --apply && harna validate
# [!declared-surface] src/ui/AccountView.tsx:1 — imports `Account` from container `domain`, which provides only add, deposit, secretRounding
```

- Interfaces and types (`Money`, `Account`) are dropped.
- The `index.ts` barrel is ignored, so the private `secretRounding` is proposed. The help says "the root module's re-exports" first.

### B4 (medium): no transitive ring for TS file edges

`harna dependents src/domain/money.ts` reports `2 direct, 0 knock-on (ring 2)`, but `AccountView.tsx` imports `account.ts`, which imports `money.ts`.

`affected --base` on a `packages/shared` change lists only `domain` as an importer, not `ui`.

### B5 (medium): `no-cycles` ignores TS cycles

1. Write `src/domain/a.ts` importing `./money`, and make `money.ts` import `./a`.
2. Run `harna add-rule --id acyclic --text t --rationale r --check no-cycles && harna scan && harna validate`.
3. The output is `no violations found`.

The same holds for two containers in one layer importing each other.

### B6 (medium): serde attributes ignored in Rust shapes

- `#[serde(rename = "acct")] pub account: String` against TS `account: string`: PASS. The wire field is `acct`, so this is a silent miss.
- `#[serde(skip)] pub cache: u8` gives the false positive `missing [cache]`.

### B7 (medium): TS field extraction gaps that cause false positives

- Untyped initialized class fields (`at = 0;`) are not read.
- Quoted keys (`"id": string`) are not read.
- JSON Schema `allOf`/`$ref` is not resolved.

### B8 (medium): `declared-surface` false positive on a namespace import of the public barrel

`import * as D from "@domain/index"` errors, although every name `index.ts` exports is provided.

### B9 (low): `--runs .` is silently dropped

`harna service add web --containers client,ui,domain --runs .` (or `service set web --runs .`) leaves no `runs` in `services.toml`. A root-level package is a legitimate deploy folder.

### B10 (low): write-time validation is incomplete for corridors

`harna service corridor add y --from api --to web --message M=server/src/lib.rs::Nope` is accepted ("added corridor y"). Validate then errors with `names Nope, which server/src/lib.rs does not declare`. The README promises that "what validate would reject is refused at write time".

### B11 (low): `dependents` rejects a stem

`harna dependents money` gives `error: no digest module matches money`, and so does `domain/money`. The help says "crate-relative stem, or file name". Only `money.ts` and the full path work.

### B12 (low): every scan dirties the tree

A no-op `harna scan` rewrites `generated_at` in `.harna/digest/index.json`, so `git status` is never clean. `affected` then counts digest files among "N changed file(s)".

### B13 (cosmetic): misleading info when a shape type is missing

When the shape type is renamed away, validate also prints `[?corridor-shape] ... has no named fields to compare (an enum, a tuple or an alias)`. The type does not exist at all; the accompanying service-coherence error says so correctly.

## Friction

- `container set --help` lists `crate:NAME` for `--gateway` but not `npm:NAME`. TS users must find it in the README.
- `validate` on a stale map passes with only a warning. In this field test, almost every "PASS" before I learned to `scan` first was a lie. Either auto-scan the changed files, or fail on staleness.
- The corridor-shape rule "case and `_` ignored" appears only in `harna checks`. That is the first question a TS-mirror author asks.
- `missing [], extra [memo]` prints empty lists.
- `status` reports "score: 100 (A)" and "tests: 0/0 components (100%)" on a project with no rules, components or tests.
- `place` output is mostly generic advice; only the "similar:" line was specific.
- TS files never become components (`manifest: ... 0 components`), so component-level tools (tests, kind-coverage) have nothing to act on in a TS project.

## Suggestions, in priority order

1. **Fix `validate --changed` for TS (B1).** Treat `.ts`/`.tsx`/`.js` as changed files. Never run corridor or service checks against a partial map; fall back to the committed digest for unchanged files. This is the per-burst gate agents run constantly.
2. **Resolve `extends` and intersection bases across files (B2)** with the same import resolution the map already has, including workspace packages. Also read untyped class initializers and quoted keys (B7).
3. **Honour `serde(rename)`, `rename_all` and `skip` in Rust shapes (B6).** rename is a silent wrong-pass today.
4. **Make `container surface` TS-aware (B3):** read the `index.ts` barrel's re-exports first, and include exported interfaces, types and enums.
5. **Detect cycles in the TS file graph and between containers (B5).**
6. **Compute transitive rings for TS edges** in `dependents` and `affected` (B4). In `affected`, name the base-map importers of a deleted file in the "why" line.
7. **Accept a namespace import of a module whose exports are all provided (B8).** Also decide whether side-effect imports of private modules count.
8. **Fail, or auto-scan, when `validate` sees a stale map.**
9. Check `package.json` dependencies for `npm:` gateways, as `crate:` does with Cargo.toml.
10. Small fixes:
    - write-time check of `file::Type` (B10)
    - `--runs .` (B9)
    - stem lookup in `dependents` (B11)
    - no-op scan churn (B12)
    - document `npm:` in the `--gateway` help
    - drop empty `missing []`/`extra []`
    - optionally resolve JSON Schema `allOf`/`$ref`

## Regression stories worth adding to `tests/suite.rs`

- B1: `validate --changed` on a clean TS+services tree must not error.
- B2: a base interface imported from another file must give no corridor-shape error.
- B6: serde rename must be honoured.
