# Field test: Rust workspace, built by layers (harna 0.9.1)

Date: 2026-10-20 · Brief: research/field-tests/suite/rust-workspace.md · Windows 11 + Git Bash
Project: `ft092-rust` in scratchpad (deleted at the end).

## What I built

A Cargo workspace (zero external deps, `--offline`), 6 crates, all scaffolded with
`harna scaffold --new-crate`:

| Layer (depends_on) | Container / crate | What |
|---|---|---|
| domain (none) | `money` | `Money` (i64 minor units, checked add/sub, Display), `AccountId` |
| domain | `events` | `PostingCreated` — the event both services share; line wire format |
| storage (domain) | `store` | in-memory append-only `Repo` |
| app (domain, storage) | `ledger` | `post_entry`, `balance`, `refund` use cases |
| services (domain, app, storage) | `api` (bin) | stdin request -> `PostingCreated` lines on stdout |
| services | `worker` (bin) | consumes `PostingCreated` lines, prints totals |

`printf 'post alice 500\npost bob 120\npost alice -75\n' | api | worker` -> `alice: 4.25 / bob: 1.20`.
3 unit tests pass. Services `api` (owns `db:ledger`, @ledger-team) and `worker` (owns `db:totals`, @ops),
corridor `postings` (event, api -> worker, `PostingCreated`), readiness `health,backups,migrations`,
contracts frozen for `money` and `ledger` at 1.0.0, rule `money-exact` (banned-api `f64 => Money`),
domain layer owners `@core`, hooks installed.

## Bugs (with exact repros)

All in a workspace like above (`harna init`, containers via `harna container add` + `scaffold --new-crate`).

### Bug 1 (critical): a declared corridor makes `validate --changed` — the pre-commit gate — BLOCK every commit that does not touch the shape file
```
harna service add api --containers api
harna service add worker --containers worker
harna service corridor add postings --kind event --from api --to worker \
  --message PostingCreated=crates/events/src/posting.rs::PostingCreated
harna scan; git add -A; HARNA_SKIP_HOOK=1 git commit -m x
harna validate --changed        # clean tree
```
Output:
```
no changed .rs files — running manifest-level checks only
[?corridor-shape] ... service `worker` is on corridor `postings` but its code never names `PostingCreated` ...
[!service-coherence] .harna/services.toml — corridor `postings`: message `PostingCreated` names `crates/events/src/posting.rs`, which the map does not hold
  fix: point the shape at a source file (<file>::<Type>), or run harna scan
verdict: BLOCKED
```
Same with any changed .rs not including `posting.rs`; PASS only when `posting.rs` itself is changed. Full `harna validate` and `harna preflight` PASS on the same tree. With `harna hooks install`, `git commit` is blocked; the advice "run harna scan" does not help. Cause appears to be: the corridor/shape checks run against the partial map of changed files only. The `corridor-shape` info for `worker` is a false positive for the same reason (worker names `PostingCreated` in main.rs/consumer.rs).

### Bug 2 (high): unknown keys are silently dropped on save, and doctor misses them in rules/manifest
```
sed -i 's/^check = "banned-api"/chek = "banned-api"/' .harna/rules.toml
harna doctor          # 0 fail; "rule-bindings  no bindings (all rules advisory)"
harna validate        # PASS — the rule's enforcement silently vanished
harna add-rule --id x --text y --rationale z
grep -c chek .harna/rules.toml   # 0 — dropped, no warning
```
Same for manifest (`depends_om` dropped by `harna container set events --description ..`) and services.toml (`ownres` dropped by `harna service ready ...`, even though doctor FAILs it). `migrate --check` itself says "the next save would drop it" — writers should refuse (or preserve) instead.

### Bug 3 (high): a fn re-exported under the same name as its module is not frozen
`ledger/src/lib.rs`: `pub mod post_entry; pub use post_entry::post_entry;`
```
harna contract freeze ledger --version 1.0.0
harna contract show ledger      # post_entry: pub mod post_entry   (no fn signature)
# add a param to `pub fn post_entry(...)` on a continuation line
harna validate --changed        # no contract finding
harna contract freeze ledger --version 1.0.1   # accepted
```
`harna container surface ledger` also lists only `post_entry` (the mod). This pattern (`mod foo; pub use foo::foo;`) is very common and exactly what `harna scaffold` produces (file per component named after its fn).

### Bug 4 (high): `affected`/`dependents` do not follow crate-root re-exports
```
echo "// x" >> crates/money/src/money.rs; harna scan
harna affected --base HEAD
# containers importing them: none
# run: cargo test -p money
harna dependents crates/money/src/money.rs   # nothing imports ... directly
```
The same edit in `crates/money/src/lib.rs` gives importers api, ledger, store, worker and `cargo test -p api -p ledger -p money -p store -p worker`. CI routing would test only `money` for a change to `Money`'s implementation. (The "crates depending on them" line lists them, but `run:` does not use it.) `services: []` too, although both services run code that depends on money.

### Bug 5 (high): parity does not open debts for importers through crate-root re-exports
```
sed -i 's/AccountId/AcctId/g' crates/money/src/account.rs crates/money/src/lib.rs
harna scan; harna parity open rename-account
# parity `rename-account` gen1: 0 open — nothing owed
harna diff   # "contents changed (surface stable): crates/money/src/lib.rs"
```
4 modules `use money::{AccountId, ..}`. lib.rs's `pub use account::AccountId` change is judged "surface stable" (re-exports not part of the surface). README claims "importers through a crate's re-exports too". (`contract` catches it if money is frozen.) Also: renaming a method (`PostingCreated::decode` -> `parse_line`, called by worker as `events::PostingCreated::decode`) -> nothing owed.

### Bug 6 (medium): doctor accepts a stale `harna-mcp`
`~/.cargo/bin/harna-mcp.exe` is 0.3.37 (Oct 18) beside harna 0.9.1. `harna doctor`: `ok agent-wiring harna-mcp server binary on PATH`. Via MCP, `harna_validate` answers `this repository's .harna data uses schema v4, but this harna understands v1`. The suite README step 1 only installs `harna-cli`; it should install `harna-mcp` too, and doctor should compare versions.

### Bug 7 (low): `no-cycles` and `service-talk`/`layer-boundary` miss leading-`::` paths and fn-local brace `use`
Repros in break list 1b/5c: `::api::routes::handle(..)`, `use ::api::routes;`, `fn r() { use api::{routes}; }`, `::ledger::balance` in a lower layer.

### Bug 8 (low): readiness and ownership normalization
`harna service ready api health "todo: later"` / `"TODO: wire later"` / `"FIXME"` / `"???"` pass preflight `ops`; bare `TODO` is accepted at write time (unlike `n/a`) and only fails at preflight. `--owns "db: ledger"` is not normalized and duplicates `db:ledger`.

### Bug 9 (low): `harna scan` with no code changes rewrites `generated_at`
`.harna/digest/index.json` becomes modified after every scan -> dirty tree / noise commits.

## Friction

1. Greenfield start: `place`/`plan` before any code just say "CODE MAP MISSING"; nothing helps pick layers. No profile for a plain Rust backend/services workspace.
2. Plain `harna validate` reads the committed digest: an edit is invisible until `scan`, while `validate --changed` sees it. Two validates that disagree on the same tree is confusing (my first round of break tests looked like misses).
3. `corridor-shape` info for `api`: the API sends `PostingCreated` through the shared `ledger` use case (`post_entry` returns it, routes call `.encode()`), so its own code never names the type. Legit design, permanent info noise.
4. `deny` prints "worker may be depended on by: api" — sibling services in one layer may depend on each other at the cargo-deny level, contradicting service-talk.
5. `no-test-update` fires for `money` when its tests live in the same file (`#[cfg(test)]` in money.rs) and the file did change.
6. `harna owners` without arguments says "no paths to route" — expected the ownership table.
7. Digest prints `[onboarding: ...]` header twice and does not mention frozen contracts (a fresh agent cannot see `money` is frozen at 1.0.0).
8. MCP `initialize` returns `capabilities: {}` and `serverInfo: rmcp 0.3.2` (confirmed on the current 0.9.1 build, see MCP section).
9. Windows: git CRLF warnings on every generated file; harna writes LF. A `.gitattributes` from `init` would help.

## MCP

The `harna-mcp` on PATH was 0.3.37 (Bug 6), so I built the current one into scratch
(`cargo build --release --offline --locked -p harna-mcp --manifest-path <harna>/Cargo.toml --target-dir <scratch>/mcp-target`,
nothing written in the repo) and drove it over stdio with raw JSON-RPC.

- `initialize` -> `{"capabilities":{},"serverInfo":{"name":"rmcp","version":"0.3.2"}}`. **No `tools`/`resources`
  capability advertised** (MCP spec: a server offering tools must declare it; strict clients may never call
  `tools/list`). serverInfo should say `harna-mcp 0.9.1`.
- `tools/list`: 49 tools (README says 48). `harna_service` covers add/set/corridor/require/ready.
- Write-time refusals work over MCP, same text as CLI:
  `harna_service {action:set, name:worker, owns:["DB:LEDGER"]}` -> `isError:true`, "resource `DB:LEDGER` is owned by service `api` — one service writes it";
  `{action:ready, facet:backups, answer:"n/a"}` -> "`n/a` needs its reason".
- `harna_onboarding`, `harna_status` answer correctly (onboarding carries services, corridor, handoff).
- **Bug 10 (critical for agents): `harna_validate` (with or without `changed_only`) and `harna_preflight` never answer**
  — no response within 60 s, while other calls on the same connection are answered. CLI `harna validate` takes < 1 s.
  During the hang a child process is alive: `"git" check-ignore -q .harna/qualities.toml` (sampled via
  `Get-CimInstance Win32_Process`). Likely a git subprocess spawned without `stdin(Stdio::null())`, inheriting
  the MCP stdio pipe on Windows. The old 0.3.37 binary did answer `harna_validate` (with a schema error).
  Repro (Git Bash, in any harna repo):
  ```
  { printf '%s\n' '{"jsonrpc":"2.0","id":1,"method":"initialize","params":{"protocolVersion":"2024-11-05","capabilities":{},"clientInfo":{"name":"t","version":"0"}}}' \
      '{"jsonrpc":"2.0","method":"notifications/initialized"}' \
      '{"jsonrpc":"2.0","id":7,"method":"tools/call","params":{"name":"harna_validate","arguments":{}}}'; sleep 60; } \
    | harna-mcp --root .      # only the initialize response ever arrives
  ```
  Since the AGENTS contract tells agents to call `harna_validate` after every edit burst, this blocks the MCP flow.

## Suggestions, priority order

0. Fix Bug 10: `harna_validate`/`harna_preflight` hang over MCP on Windows (null the stdin of every git child; add an MCP smoke test that calls validate over stdio). Declare `tools`/`resources` capabilities in `initialize`.
1. Fix Bug 1: in `validate --changed`, run service/corridor checks against the full digest (or the digest overlaid with the changed files), never the changed-files-only map. Add a suite story: corridor declared + clean tree + `validate --changed` must PASS; preflight and pre-commit must agree.
2. Resolve crate-root re-exports everywhere the import graph is used: `affected` (routing), `dependents`, parity fan-out, `no-cycles`. A change to `money.rs` must route to every crate that imports `money::Money`.
3. Contracts: freeze both the module and the same-named re-exported fn (key them e.g. `post_entry` (mod) and `post_entry()` (fn)), since `scaffold` produces exactly that shape.
4. Never drop unknown keys on save: refuse the write with the `migrate --check` message; have doctor report unknown keys in every data file (rules and manifest included); for `rationle`, say "unknown key `rationle` (did you mean `rationale`?)".
5. Doctor: compare `harna-mcp --version` with `harna --version`; suite README: install harna-mcp as well.
6. Readiness: treat any answer starting with TODO/TBD/FIXME (case-insensitive, with or without suffix), or placeholders (`?`, `-`, `none`) as unanswered; refuse them at write time like `n/a`.
7. Normalize resource ids (trim around `:`) before the one-owner check.
8. Handle `::crate::path`, fn-local brace `use`, `extern crate` in the import extractor.
9. `harna scan` should not rewrite `generated_at` when nothing changed; `harna owners` with no args should print the table; digest should list frozen contracts.
10. A starter profile for "Rust services workspace" (domain/storage/app/services with services + corridor + readiness skeleton).
