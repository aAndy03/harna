`cargo fmt --check`, `harna validate` (0 errors, 6 info, 1 acknowledged), `harna preflight` (PASS), `harna doctor` (16 ok) are green.

## 3. Findings

Severity: B = bug / wrong output, F = friction, G = gap, + = good.

**F1 (F) scaffold defaults to `src/<layer>/<container>`, not the crate layout.** Scaffolding into a new container in a Cargo workspace creates `src/app/household_app/...` at repo root with "not wired: no crate root". I had to `rm -rf src` and cut the stray layers out of the manifest by hand (no `harna layer remove` / `container remove`).
```
harna scaffold --layer app --container household-app --name households ...
created src/app/household_app/bills.rs ... not wired into the module tree: no crate root (src/lib.rs or src/main.rs) above it
```
Workaround: the FIRST scaffold of each container must pass `--path crates/<crate>/src/<file>.rs` with a single `--name`; that fixes the container path for later calls. Suggest: infer the crate from workspace members, or refuse a container path outside any crate; add `container remove`.

**F2 (F) `--path` keeps the file name verbatim and component names are globally unique.** To satisfy uniqueness I used `route-expenses`, `store-expenses`; files became `route_expenses.rs` / `store_expenses.rs`, which tripped `name-cluster` (my own rule). Fix cost 8 `harna move` calls. Suggest: unique per container, or a separate `--file`.

**F3 (G) data scaffold template is not compilable and clashes with `no-panic`.** `scaffold --kind data` emits a loader whose doc wiring uses `fn load_currency-table()` (hyphen), `include_str!("../crates/household-domain/src/currency_table.toml")` (wrong relative path), `.expect(...)`, placeholder `key/value` entries, and needs a `toml` dep it does not mention. The toml+loader pair concept is good; I rewrote both files. Suggest: snake_case, path relative to the file, return `Result`.

**F4 (F) scaffold stubs pollute advisories.** Each primitive gets a self-referencing `tests = [<itself>]` and a fake `constructs()` test. After real code replaced the stub, `tests-declared` said "declares X as a test, but the file contains no test code"; fixed via `container tests --remove` (8 times). Compound parents (`money`, `ledger`, `split`...) show in `status` as `untested` even though their children are tested. `no-test-update` also fires on files changed only by `pub mod` wiring.

**F5 (B) `validate` reads the digest, not the tree, after `move`.** After the 8 moves, `harna validate` still printed old name-cluster findings until `harna scan`.
```
$ harna move ...route_balances.rs ...balances.rs   # x5
$ harna validate   -> [?name-cluster] still lists route_*.rs
$ harna scan; harna validate -> no violations found
```
`move` should refresh the digest, or `validate` should say "digest stale".

**F6 (G) `declared-surface` makes me enumerate names twice.** `pub use` in `mod.rs` and `--provides A,B,C...` (32 names) in the manifest. I copied names out of the error list; there is no suggest/auto mode. The check is by simple name, so two different `Balances` types would collide.

**F7 (B) parity: false positives, and the real caller missed.** Renaming `Households::list_members` -> `members_of`:
```
! open crates/household-app/src/bills.rs        imports a module with a breaking change: ...households.rs: signature removed: pub fn list_members
! open .../expenses.rs, .../settlements.rs      (same)
```
Those three import `ensure_members`, not `list_members` (granularity is module, not symbol). The one real caller, `routes/households.rs` (`a.households.list_members(..)` through a struct field), was NOT listed; `cargo build` found it. For an additive trait change (`ExpenseRepo::get_expense`) implementors are only listed if I had already edited them.

**F8 (F) `place`/`plan` placement is keyword similarity, not architecture-aware.** "sqlite persistence implementing the repository ports with migrations", asked after the store layer existed, returned `api/routes/mod.rs` and `app/reports.rs` and nothing from `household-store`. "fetch a single expense by id through the repository port, service and endpoint" listed only api files and missed `ports_core.rs`, `store/repos/expenses.rs`, `app/expenses.rs`. Positive: "rules to respect", "tools that fit", non-goals and prior attempts were good, and `place` before `scan` says clearly "CODE MAP MISSING".

**F9 (F) `hotspot` fires on brand-new files.** `ports_core.rs` "3 commits x 44 items = 132" came from my own bursts; 2-4 hotspot infos stayed in every `validate`.

**F10 (F) parity ids are free text and each `open` creates a new event** (8 events, all zero-debt). Deriving the id from HEAD/short message would save a decision.

**F11 (F) dev-dependency across layers is not flagged.** `household-api` has `[dev-dependencies] household-store` and `tests/api.rs` imports it, yet the api layer does not depend on store; neither `cargo-layering` nor `layer-boundary` reported it. Maybe intended, but undocumented; `place` labels test files `layer (ungoverned)`.

**F12 (F) `deferred add` hint confusing.** For a declared milestone it still prints "(declare it first: `harna roadmap add v0.2-hardening ...`)".

**F13 (+) Rules bind real checks and the messages say what to do.** `banned-api` (with `a => b` replacement), `no-panic`, `suppression-reason`, `born-size`, `no-cycles` (found a real `database <-> migrations` cycle), `gateway-ownership` (axum leaked into the server) each fired on a real mistake with a `fix:` line.

**F14 (+) `harna move` is trustworthy.** Relinked manifest, rules, `mod` declarations in one step; for the `model/` move it created `model/mod.rs` and cleaned lib.rs.

**F15 (+) `non-goal` / `lesson` / `roadmap` surface in `plan`/`place`/`status`.** Verified end to end.

**F16 (F) pre-commit output on Windows is dominated by git CRLF warnings** (`.githooks/pre-commit`, workflow, digest JSON...). Suggest `.gitattributes` with `eol=lf` for `.harna/` and generated hooks.

**F17 (info) `harna dependents <file>` says "nothing imports" for `money_core.rs`** because consumers go through the `money` re-export; `whereis Money` worked. `metrics` reports "34 undeclared" edges without naming them.

Non-harna note: a single 200+ line shell heredoc in my agent shell failed with "unexpected EOF" three times; <=100-line commands worked. Recorded as a `harna lesson` in the project.
