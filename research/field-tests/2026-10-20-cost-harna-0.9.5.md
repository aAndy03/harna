# Cost experiment — WITH harna (0.9.5 rc, `--version` prints 0.9.4), 2026-10-20

**Cost** (from the run result): 100,070 tokens, 27 tool calls, 4 min 31 s. Control (same day): 85,915 tokens, 9 tool calls, 2 min 31 s. 0.9.4's pair: 106,338 vs 86,159.

Product: Rust workspace `crates/{domain,events,storage,app,api,worker}` — Money in minor units
(domain), in-memory LedgerStore (storage), `record_posting`/`apply_event` use cases (app), shared
`events::PostingCreated { account, amount_minor }` crate, two binaries (api: stdin commands ->
encoded events on stdout; worker: events on stdin -> balances). 10 test binaries, 8 tests, every
layer has one. `echo "cash 100\ncash -30" | api | worker` prints balances 100 / 70.

Layers declared: domain [] ; contracts [] ; storage [domain] ; application [domain,storage,contracts] ;
services [application,domain,contracts,storage], isolated = true (api, worker).
Services: api (crates/api), worker (crates/worker). Corridor `postings` (event) api -> worker
carrying `PostingCreated=crates/events/src/lib.rs::PostingCreated`.
Rules bound: layer-boundary, cargo-layering, sibling-isolation, service-talk, corridor-shape, contract.

## Findings for harna

- BUG (high): `layer-boundary` and `cargo-layering` stayed silent for crate-level imports and
  Cargo deps that cross declared layers (probes 1b, 3; probe 1 was only caught as a cycle). Rules
  were bound with empty scope; `validate` reported PASS. Either these checks do not map
  `crates/<x>` containers to crate names, or an absent/empty `depends_on` is treated as
  unconstrained — in the latter case `layer set --depends-on ""` should say so, since "imports
  nothing" is the commonest intent for a domain layer.
- BUG (medium): `validate --check <id>` prints "1 violation(s) (1 error...)" + BLOCKED while
  showing zero violation lines when the error belongs to another check.
- Friction: `service corridor add --message Name=<file>::<Type>` refuses before the file exists,
  so the corridor cannot be declared in the plan step (forces a second pass after code).
- Friction: `harna scan` on a clean, just-committed tree rewrites 4 digest shards (likely CRLF
  under core.autocrlf on Windows) — noisy `git status` after every probe.
- `place` on a fresh repo mostly echoes declared descriptions; 3 boilerplate paragraphs repeat
  on every call.
- Good: `service-talk`, `corridor-shape`, `contract` + `affected` gave precise, actionable,
  one-line messages; corridor-shape's info nudged the api to name the event type explicitly.

## Cheaper vs more expensive

More expensive (vs a no-harna build): ~13 KB of help/checks text read up front (~3.5k tokens),
~8 extra calls for declaring layers/services/corridor/rules and scan/validate cycles, plus ~4 calls
diagnosing silent layer checks. Roughly +12 calls and +8-10k tokens over a plain cargo build.

Cheaper / added value: probes 4 and 5 produce one precise line each instead of reading compiler
fallout across crates; `affected` gives the redeploy set (api, worker) without grepping;
service-talk catches the cross-service import even when cargo would compile it (api with a lib
target). Where cargo already errors (1, 2, 5) harna adds naming, not detection. Probe 3 and the
layer probe were caught by neither, so the layering promise did not pay off in this run.
