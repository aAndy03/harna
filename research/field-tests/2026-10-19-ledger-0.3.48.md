# HARNA_FEEDBACK.md — field test of harna 0.3.48 (ledger backend)

Severity: bug | friction | gap | good. Written as I go.

## Burst 0 — init
### 0.1 init (good/friction)
- Cmd: `harna init --agents` in an empty git repo.
- Result: created `.harna/{manifest.toml,rules.toml,decisions/}` + AGENTS.md. "next: `harna scan`, add rules, and wire the harna MCP server" — no hint on HOW to wire the MCP server (what binary, what config). [friction]
- AGENTS.md contains an empty `<!-- harna:begin --> <!-- harna:end -->` block until `harna render` runs. [friction: init could render once]
- AGENTS.md is ~70 lines of harna-internal release history ("Honesty (0.3.32): ...", "Seams (0.3.31)") that is noise for a fresh user project; most of it is about harna features rather than this project. [friction]

### 0.2 scaffold before any crate exists (friction)
- Cmd: `harna scaffold --layer domain --container money --name amount --kind primitive --path crates/domain/src/money/amount.rs --role base`
- Output: "created ... registered ... not wired into the module tree: no crate root (src/lib.rs or src/main.rs) above it".
- Meaning the ritual "scaffold first, then fill" needs a Cargo skeleton (crate roots) BEFORE scaffolding, or mod wiring is skipped silently-ish. Not stated in docs/help. [friction]
- The generated header comment says "Scope: `src/domain/money`" for a `--path` primitive (ignores --path); the compound variant printed the right scope `crates/domain/src/money/currency`. [bug, cosmetic]
- Scaffold default path is `src/<layer>/<container>/<name>`, which does not fit a multi-crate workspace; every call needs `--path`. No way to declare a per-layer crate root once (e.g. layer.root = "crates/domain/src"). [gap]
- Compound scaffold auto-invented a child "currency-core" (struct CurrencyCore) I did not ask for. [friction]

## Burst 1 — manifest + scaffold (≈ 75 harna calls, mostly one scaffold per file; 0 lines of real code yet)
### 1.1 adopt on a bare Cargo workspace (good)
- Cmd: `harna adopt` (after hand-writing 5 crate skeletons). It printed a draft manifest: one layer per crate (`ledger_api`...), `depends_on` derived from Cargo deps. Printed only (not written) — I then built the manifest through scaffold/layer set. Names are the crate names (`ledger_domain`), not what I wanted (`domain`); no `--write`/`--rename` option. [good + gap: no `adopt --write`]
### 1.2 scaffold wiring (good)
- After crate roots exist, `harna scaffold` creates mod.rs and adds `pub mod x;` to the parent. Container dir gets mod.rs. Works with workspace crates via --path. Nice.
### 1.3 scaffold cost (friction)
- One component per invocation: 40 scaffold calls for 40 files. A `--names a,b,c` or a TOML plan (`harna scaffold --plan file`) would cut this a lot. [gap]
- `--role` only stamps the container on the first call; later calls ignore it silently. Layer role needs a separate `harna layer set`. Layers need a separate `layer set --depends-on` too (scaffold creates the layer empty with no deps).
- Component names must be unique across the whole manifest (`error: component 'error' already exists`) — I had `domain/kernel/error` and `api/http/error`. Forced rename to `http-error`. Surprising for per-crate layout. [friction]
- scaffold of `budget` container + `budget` component -> `budget/budget.rs`; clippy then fails with `module_inception` ("module has the same name as its containing module"). Scaffold should refuse/warn when name == container. [bug-ish, cost me a `harna move`]
- `harna move budget.rs plan.rs` (good): relinked manifest, rewired mod; component name stays `budget` while path is plan.rs - slightly confusing but fine.
- `harna layer set server ...` fails if the layer does not exist yet; ordering matters. Message is clear though.
### 1.4 validate noise on a fresh project (friction)
- First `harna validate`: 21 info, 0 error: 19x `[?rules-coverage] ... no scoped rule watches layer ... container ...` (one per container; each with 2 lines of output) before any rule existed; vanished once I added global-scope `crates` rules. Verbose; a single line "N containers uncovered" would do.
- `[?doc-claims] AGENTS.md:16 — .harna/terms.toml does not exist` and `:30 roadmap.toml does not exist`: AGENTS.md written by `harna init --agents` itself claims files that init never creates. harna flags its own template. [bug, false positive on fresh init]
### 1.5 add-rule discoverability (friction)
- `harna add-rule --help`: "Budget for a budget check (see `harna doctor` for the list)" but `harna doctor` lists no checks. The only list I found was the error text from an unknown `--check nonsense` (good message, lists 50 checks). A `harna checks` / `harna rules --checks` command with 1-line descriptions + which args each takes (--limit/--value) is missing. [gap]
- I had to guess value syntax for banned-api. `--value "f64 => rust_decimal::Decimal"` worked (the `=>` replacement form) — found it only in the task brief.
### 1.6 gateway = crate:rusqlite (good/friction)
- `harna container set sqlite --gateway crate:rusqlite` accepted. `--help` for --gateway lists only `fs | fs:write | net | process | base`; `crate:` form undocumented in help. [friction]
- `harna deny` then emitted a `bans` entry `rusqlite wrappers=[ledger-storage] reason="gateway crates/storage/src/sqlite only"`. Good: compile-time + source-level. But NOTE the wrapper granularity is crate (ledger-storage), not the container, which is what cargo-deny can do.
### 1.7 harna deny output (bug)
- `harna deny` wrote `crates/domain/clippy.toml` from my banned-api rule with
  `[[disallowed-methods]] path = "f64"` and `path = "f32"`. clippy prints `warning: expected a function, found a primitive type` for both (disallowed-methods can't ban types; would need `disallowed-types`, and primitives can't be banned there either). The ban is silently ineffective at compile time and every clippy run now prints warnings. [bug]
- Also path `Utc::now` is not a full path; clippy needs `chrono::Utc::now`. I will re-add the rule with the full path.
- First `harna deny` run exited with status 2 though it wrote files fine; a second run exited 0. Unclear what 2 meant (maybe "files changed"). [friction]
- deny.toml lists `ledger-storage` wrapped only by `ledger-server`, but my application/api crates use ledger-storage as a **dev-dependency** for integration tests -> `cargo deny check bans` would flag it (cargo-deny not installed here so unverified). harna doesn't distinguish dev-deps in layering. Will see if validate crate-conformity complains. [unverified]

## Burst 2 — domain crate (≈ 14 files, 37 unit tests) and storage crate (≈ 12 files, 5 unit + 6 integration tests)
Harna commands: ~10 (scan x3, validate x5, parity open x1, move x7, acknowledge x2, scaffold x3 more). Code work: ~25 files written by hand.

### 2.1 no-copy-paste caught real duplication (good)
- `harna validate --changed` -> `[?no-copy-paste] budget/plan.rs and ledger/account.rs share 2 normalized block(s)` (also transaction.rs, recurring/template.rs). It was the 4x copy-pasted `XxxId(Uuid)` newtype boilerplate. I replaced it with a `define_id!` macro in a new kernel/ids component. The finding was Info but pointed exactly at a legit refactor.
- Wording friction: it says "files share N blocks" but not WHICH block/lines, so I had to guess; a line range per file would save a lookup.

### 2.2 no-cycles caught a real import cycle (good)
- `[!no-cycles] crates/storage/src/sqlite/connection.rs: import cycle: connection.rs -> migrations.rs -> connection.rs` (migrations imported `sql_err` from connection, connection called `migrations::run`). Rustc doesn't care but it is real coupling. Fixed by moving `sql_err` into codec. Error severity by default - OK.

### 2.3 folder-size + name-cluster pushed a better layout (good)
- With my own rules (folder-size limit 10): `[?folder-size] crates/storage/src/sqlite — 11 source files (budget 10)` and `[?name-cluster] 7 files share the name token 'repo' (account_repo.rs, ...) — that is a folder that was never created`. Exactly right, and `harna move a_repo.rs repos/a.rs` created repos/mod.rs, rewired `pub mod`, and rewrote `use` paths in OTHER files (store.rs) — great.
- But friction: `harna move` does not rewrite `super::` relative paths INSIDE the moved file (`use super::connection::Db` broke -> had to sed to `crate::sqlite::connection`). Its output says "check: build now" so it's honest. [friction]
- 7 separate `harna move` invocations; no glob/batch (`harna move 'sqlite/*_repo.rs' sqlite/repos/`). [gap]
- name-cluster fires on suffix tokens (`*_repo.rs`) but then the suggested folder name needs me to also strip the suffix (account_repo -> repos/account). It did not suggest the target names. [friction]

### 2.4 no-test-update vs integration tests (friction + gap)
- Components default to `tests = [<own file>]` (in-file `#[cfg(test)]`). My storage repos are tested by `crates/storage/tests/repos.rs` (integration). `validate --changed` then said for each of 9 files: `[?no-test-update] component 'account-repo' changed, but none of its registered tests did`. 
- There is NO CLI to set a component's tests (scaffold has no --tests; `container register` neither; `container set` is container-level). I hand-edited `tests = [...]` in manifest.toml with perl, against AGENTS.md's "Do not hand-edit files under .harna/". Afterwards `harna tests --component rate-repo` correctly printed `run: cargo test -p ledger-storage --test repos` (nice: resolves crate + test target). [gap: need `harna component set <name> --tests a,b` ]
- For pure trait files (ports/repositories.rs) there's nothing to test; `harna acknowledge add no-test-update --file ... --reason ...` worked well (good).

### 2.5 scaffold-then-fill hygiene (friction)
- I deleted scaffold stubs to overwrite them with real code (Write tool refuses to overwrite unread files). While files were absent `validate --changed` reported 60 errors (`manifest-path`, `tests-declared`: "component ... path does not exist; fix: run harna scaffold") — expected, but the same fix hint applies after I `rm`: scaffold would refuse because the component exists. Nothing in harna detects an UNFILLED stub (`// TODO: fields` + `fn new() -> Self { Self {} }` passes validate). A `todo-stub` check (scaffold marker still present) would catch half-finished scaffolds. [gap]
- The stub bodies (struct X {TODO}) are mostly useless for real code: I discarded every one. A `--bare` option emitting only the module doc header would be better. [friction]

### 2.6 parity open with no baseline (friction)
- `harna parity open domain-born` with no commits yet: `parity gen1: 39 target(s): 0 open — nothing owed; 39 origin (your change)`. Fine and quick, but it's meaningless before the first commit (baseline HEAD does not exist) — no message saying "no baseline commit; parity needs a first commit". [friction/minor]

### 2.7 No hint about wiring harna to the compiler
- `clippy.toml` in domain stays with bogus f64 entries (see 1.7); every `cargo clippy` prints two config warnings.

### 2.8 banned-api for f64 actually works at source level (good)
- Putting `pub fn bad() -> f64` in domain/money/rates.rs: `[!banned-api] crates/domain/src/money/rates.rs:34 — 'f64' is banned here (rule no-float-money) fix: use rust_decimal::Decimal instead`. Immediate, correct line number, uses my `=>` replacement. 

## Burst 3 — application (+planning) and api + server crates; first commit
Harna commands this burst: ~35 (scaffold x7, move x9, validate x8, scan x5, parity open x2, acknowledge x1, hooks install x1, command add x4, log-decision x5, roadmap x2, render x2, handoff x1, preflight x2, deny/render). Code: ~35 files, ~3.5k lines, 75 tests.

### 3.1 Enforcement caught every deliberate violation (good) — negative test, all with exact file:line
I injected 5 violations then reverted. `harna validate --changed` reported each correctly:
- api importing storage: `[!layer-boundary] crates/api/src/http/state.rs:1 — cross-layer import 'ledger_storage::sqlite::store::Store' reaches layer(s) storage not in api's allowed set`
- application using rusqlite: `[!gateway-ownership] crates/application/src/reporting/net_worth.rs:80 — imports 'rusqlite', which only its gateway may use (crates/storage/src/sqlite)`
- domain reading the clock: `[!banned-api] ...rates.rs:110 — 'chrono::Utc::now' is banned here (rule 'clock-via-port')`
- unwrap in lib code: `[!no-panic] ...:111 — 'unwrap' can panic in production code`; test-module unwraps NOT flagged (correct).
- `#[allow(dead_code)]` : `[!suppression-reason] ...:112 — '#[allow…' suppresses a lint without saying why`. Afterwards `#![allow(dead_code, reason = "...")]` (inner attribute) was accepted.
- storage importing application: layer-boundary again. Note: dev-dependencies used from tests (application tests -> ledger_storage) are NOT flagged, which is what I wanted (tests may wire real adapters), but it is undocumented whether that is by design.
- The messages say which rule bound them and give a fix. This is the best part of the tool.

### 3.2 born-size is sharp (good) and also surprising (friction)
- Two test files I wrote were 431 and 454 lines after `cargo fmt` (they were under 400 before fmt, so my first validate passed): `[!born-size] crates/api/tests/http.rs — new file born with 454 lines — born-size budget 400`. It is an ERROR that would block commit. I split them into tests/common/mod.rs + 3-4 per-scope files (fix hint: "split into per-scope modules and register them in the manifest" - fine).
- Friction: born-size applies to integration test files too and the natural split of test files (shared `common/mod.rs`) caused `dead_code` warnings per test crate -> needed the `allow(.., reason)`. Could `born-size` have a `--scope` or exclude `tests/`? I can scope the rule but not exclude; I'd have to add a second rule. Minor.
- born-size "new file" detection relies on git state: counting files untracked-or-new vs HEAD. Before the first commit EVERYTHING is "new". Works, but numbers change after fmt so validate results flip between runs (see above). Advice: run fmt before validate in the ritual.

### 3.3 harna move (good)
- `harna move crates/api/src/handlers/accounts_handler.rs crates/api/src/handlers/accounts.rs` rewrote the grouped `use crate::handlers::{accounts_handler as acc, ...}` in router.rs and cross-crate paths (`ledger_application::planning::setup_budget` -> `planning::budget` in api). Compiled first time. 9 moves, 0 build breaks (besides the `super::` case from burst 2).
- Gap: name-cluster suggestion `move them under crates/api/src/handlers/handler/` is silly when the files are already in `handlers/` (the token duplicates the parent folder; the right fix is dropping the suffix). The fix text should detect "token == parent folder name" and say "rename, drop the token".

### 3.4 Hand-editing the manifest 3x (gap, repeated)
- I again had to perl-edit `tests = [...]` for ~28 components (twice, because I split test files and had to remap). Moving/renaming test files is not tracked by `harna move` for integration tests referenced by components? I did not try `harna move` on tests/http.rs (I split it with sed), so unverified. Still: need `harna component set <name> --tests ...` and `harna move` should relink `tests` entries (it says it does: "manifest paths, tests and rule scopes relinked").
- After splitting http.rs into 3 files `validate --changed` did NOT complain that `tests-declared` pointed to a removed file `crates/api/tests/http.rs`... because I had already sed-replaced it. Unknown.

### 3.5 Pre-commit hook (good + friction)
- `harna hooks install` wrote .githooks/pre-commit (+core.hooksPath), .claude/settings.json (PostToolUse/SessionStart/Stop hooks) and .github/workflows/harna.yml. I committed with 22 errors outstanding earlier: the hook printed `verdict: BLOCKED` and aborted. After fixing, commit went through. The output was good.
- Friction: the hook output ends with exit status 0 in my pipeline because of `| tail`, not harna's fault.
- Friction: git prints ~40 `warning: LF will be replaced by CRLF` lines for every `.harna/digest/shards/*.json` on Windows. The digest is committed; harna could write CRLF-safe .gitattributes (`.harna/** text eol=lf`) in `init`. [friction/Windows]
- `.harna/digest/` is ~25 JSON shards committed with every commit: they diff noisily on each scan (digest churn). It says "committed and diffable", but I wonder whether 25 shard files in every PR is what users want; maybe a single file or gitignored with CI regeneration.

### 3.6 preflight (good)

Harna commands: place, plan, scaffold, scan, parity open x2, validate, render, preflight, handoff --clear, commit = ~11. Code: 1 use case, 1 endpoint, 2 tests.

### 4.1 place / plan (friction)
- `harna place "report of spending grouped by tag over a date range"` returned `api/handlers/reports.rs`, `application/src/lib.rs [layer (ungoverned)]`, tests... but not `application/reporting` (net_worth / budget_report live there — the obvious home). - `harna plan` prints ALL 9 rules every time, not just the ones whose scope covers the candidate container (e.g. `no-float-money`/`clock-via-port` are scoped to domain+application, `storage-gateway` is irrelevant to an api handler). ~40 lines of output of which ~8 matter. Filter by candidate container scope. [friction]
- "decision context: none matched" even though I logged a decision about rates/conversion/money: matching is shallow.

### 4.2 parity with a real baseline (good, with one miss)
- Additive change -> `parity open tag-report`: `3 target(s): 0 open — 2 origin, 1 auto-resolved`. No manual work. 
- Breaking change to a free fn (`list_rates(svc)` -> `list_rates(svc, _limit)`): `parity open fn-change`: `5 target(s): 1 open` naming the importing module (`api/handlers/budgets.rs: imports a module with a breaking change: ...signature removed`) and `validate --changed` printed `[!parity-open] ... verdict: BLOCKED`. Exactly the intended behavior.
- **MISS (bug)**: changing a trait METHOD signature in `domain/ports/repositories.rs` (`fn has_external_ref(&self, r: &str)` -> `(&self, r: &str, include_archived: bool)`) was not seen as a surface change. `harna diff` reported `contents changed (surface stable): ...repositories.rs (body-only edits: governed by validate --changed, not the parity ledger)`, `parity open` -> `3 target(s): 0 open`, validate PASS, while `cargo check` fails in ledger-storage (`E0050 method has_external_ref has 2 parameters but the declaration in trait has 3`). The digest even stores the new method signature text; it just does not diff trait items. A port/trait change is the single most parity-relevant change in a ports-and-adapters architecture. Repro: edit any trait method in a `pub trait`, `harna scan; harna parity open x`. [bug, high value]
- `parity auto fn-change` after I REVERTED the breaking change said `0 auto-verified, 1 still open` (stale); only `parity open fn-change` again (revise) re-evaluated and closed it. Intuitive expectation: `auto` re-verifies against the working tree. [friction]
- Event files accumulate in `.harna/parity/` (4 closed events after 4 bursts) — `harna archive` exists; fine.
