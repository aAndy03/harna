# What deno shows harna is missing

**Subject:** [denoland/deno](https://github.com/denoland/deno). 108k stars. Shallow clone of
`a18ce33` (2026-10-06). 682k Rust lines and 511k JS/TS lines outside tests, so about 1.2M
lines. About 90 workspace crates under `cli/ → runtime/ → ext/* → libs/*`.

**Method:**
1. harna mapped deno automatically. `adopt`, `scan`, `validate` and `metrics` ran on the clone
   with the 0.3.43 release binary. What harna got wrong there is itself evidence (part A).
2. Two Haiku readers covered what a map can't see: organization, and orchestration (tooling,
   tests, CI, agent docs).
3. Every load-bearing claim was re-checked against the tree before it went into this file.

Each gap below is generalized. It is an extension of logic or tools harna already has, not a
deno feature to copy. Priority: **P1** = harna misreads big repos without it.
**P2** = the next real capability. **P3** = valuable polish.

---

## A. Seeing a big repo correctly (harna's own run on deno)

| # | Gap | Evidence | Extend |
|---|-----|----------|--------|
| A1 | **P1 · Crate discovery assumes `<crate>/src/`.** | Only 6 of ~90 crates have `src/`; most use `[lib] path = "lib.rs"` at the crate root. `adopt` drafted **11 layers** and folded the rest into one root layer. | One crate index built from Cargo data: `[workspace] members` and globs, implicit path deps, `[lib]`/`[[bin]] path`, `package =` renames, dir ≠ package name (`ext/fs` = `deno_fs`). `adopt`, `resolve` and `digest::crate_of` all share it. |
| A2 | **P1 · Cross-crate imports don't resolve.** | Same root cause: **36 edges for 1052 modules**. `deno_core::…` never maps to `libs/core`. | The A1 index feeds `crate_name_dirs`. Add `[workspace.dependencies]` renames (`v8 = { package = "deno_v8" }`). |
| A3 | **P1 · The grade does not say how much it could see.** | `metrics` printed **97 (A)** on a graph it barely saw, with 1052 modules outside every container. | Report graph coverage (resolved-import ratio, homed-module ratio) as part of the grade. Below a floor, print "ungraded: harna sees N% of this repo", not a letter. |
| A4 | **P2 · Shallow history and churn cost.** | On a 1-commit clone, hotspots ranked by item count only. `metrics` took **34s** while `scan` took 2.5s. | Detect shallow or too-short history and say "no churn evidence". Compute churn in one `git log --name-only` pass. Add a performance budget test on a large fixture. |
| A5 | **P2 · Adopt proposes one layer per crate.** | deno's real layers are top-level directory groups of many crates. | Propose layers from top-level groups, with crates as containers. Derive `depends_on` from Cargo path deps, which are exact and cheap. |
| A6 | **P1 · Checks gate before anyone adopted them.** | Day one: **174 `no-hardcoded-urls` errors** with no rule bound, and 247 granularity advisories. | Unbound content checks advise, never gate. At adoption, calibrate thresholds from the repo's own distribution (e.g. granularity at p95 lines) and record them as rules with `origin = "adopt calibration"`. |

## B. Gateways and boundaries: from tokens to capabilities

| # | Gap | Evidence | Extend |
|---|-----|----------|--------|
| B1 | **P2 · Capability-type gateways.** | `CheckedPath` has private fields ("to prevent someone constructing this outside the crate"). Only the permission layer makes one, and `FileSystem` methods require it. | Gateway kind `capability = "<Type>"`: constructing the type outside the declaring container is a violation, and holding it elsewhere is fine. The type system holds the line; harna records and checks it. |
| B2 | **P2 · Counted escape hatches.** | `CheckedPath::unsafe_new` has 42 call sites. There are 153 `allow(clippy::disallowed_*, reason = …)` sites. | Inventory in-code suppressions and escape-hatch calls per scope. Require a reason, and make the count a ratchet budget (C1). |
| B3 | **P2 · Banned APIs as rule data, generated into clippy.** | 61 `clippy.toml` files with `disallowed-methods`. `lint.js` checks that each crate's list holds the required entries. | A scoped rule `banned = ["std::fs::read", …]` with a reason. `harna deny` already writes cargo-deny bans; extend it to generate per-crate `clippy.toml`, with a drift check. The compiler then enforces what harna declares. |
| B4 | **P2 · Layer DAG on Cargo deps, not only imports.** | The layering (`cli → runtime → ext → libs`) is prose in `doc/architecture.md`, with no checker. | A `layer-boundary` mode over `Cargo.toml` path dependencies: exact, cheap, and catches a dependency before any import exists. |
| B5 | **P2 · Marker ownership.** | The doc says capabilities live in `ext/`, yet `cli/ops/` declares ops. | Generalize gateways from "facility tokens" to "markers": an attribute or macro (`#[op2]`, `extension!`) may only appear in declared containers. |

## C. Ratchets: making adoption possible on 1M lines

| # | Gap | Evidence | Extend |
|---|-----|----------|--------|
| C1 | **P1 · Baselines that may only decrease.** | `no_deno_api_in_polyfills.ts`: `EXPECTED_VIOLATIONS` maps 26 files to counts (e.g. `fs.ts: 53`) that may only go down. | A `baseline` ledger: check × file → allowed count. Over the count fails. Under it prompts "lower the baseline" (`harna baseline tighten`). This turns every error-severity check into an adoptable one on legacy code. Acks are all-or-nothing today. |
| C2 | **P2 · Count pins.** | `tests/unit/ops_test.ts`: `EXPECTED_OP_COUNT = 44`. | The inventory already counts items by kind. Add a rule "kind K in scope S counts N" to catch silent surface growth that parity's signature diff can't see. |

## D. Things that must stay in sync

| # | Gap | Evidence | Extend |
|---|-----|----------|--------|
| D1 | **P2 · Sync groups.** | 4 files carry `NOTE: ordering is important here, keep it in sync with…` (`runtime/snapshot.rs`, `snapshot_info.rs`, `worker.rs`, `web_worker.rs`), and no test enforces it. | Declare a sync group: N sites plus an extractor (a marker or list). The check requires an identical set and order. A comment becomes data. |
| D2 | **P2 · Generated artifacts registry.** | `runtime/features/data.rs` generates both `gen.rs` and `gen.js`. 11 CI workflows are generated from `.ts` and checked by `--lint` drift. | `generated = { path, by = "<cmd>", check = "<cmd --check>" }`. Generated files skip size and folder budgets, and drift runs locally. harna already does this for its own hooks and CI (`is_current`); generalize it to the repo's generators. |

## E. Repo hygiene as data

| # | Gap | Evidence | Extend |
|---|-----|----------|--------|
| E1 | **P3 · Folder allowlists.** | `ensureNoNewTopLevelEntries`: "When adding anything to this list it must be discussed!" | `allowed_entries` per folder, with a rationale. A new entry is a decision, not drift. It sits next to `folder-size`. |
| E2 | **P3 · Header rule.** | `copyright_checker.js` requires one header line per file type. | A rule with `header = "<regex>"` per glob. |
| E3 | **P2 · Referenced-by.** | `ensureNoUnusedOutFiles`: every `.out` must be referenced by a `__test__.jsonc`. | A generic check: files in scope X must be referenced from files in scope Y. This covers orphan fixtures, assets and migrations. |
| E4 | **P2 · Ignore-with-reason.** | node_compat has 386 `"ignore": true`, each with a `reason`. | Inventory `#[ignore]` and skipped cases. Require `#[ignore = "why"]`, and count them per scope (ratchet with C1). |
| E5 | **P2 · Test kinds beyond Rust files.** | 2,102 `__test__.jsonc` spec dirs with a matcher language and `.out` siblings. | A component's `tests` can name data-driven suites (`spec-dir` with a manifest file), not only `.rs` paths, so `tests-declared` and `no-test-update` cover them. |

## F. Agent guidance and docs drift

| # | Gap | Evidence | Extend |
|---|-----|----------|--------|
| F1 | **P1 · Claims in agent docs are checkable.** | CONTRIBUTING documents `./x test`/`./x spec`, which `tools/x.ts` does not define. `architecture.md` lists `third_party/` and `coverage/`, which don't exist. It also says extensions register in `worker.rs` only, but four files do it. | `validate-intent` already reconciles the version and changelog. Extend it to paths and commands cited in `AGENTS.md`/`CLAUDE.md`/`CONTRIBUTING.md`/`*instructions.md`: each must exist. |
| F2 | **P2 · One source for every agent-instructions file.** | `.github/copilot-instructions.md` is a near copy of `CLAUDE.md`; agent skills live in `.claude/skills/`. | `harna render` writes all agent-instruction files from `.harna/` data (rules, commands, layers), with a drift check, so instructions are data rendered N ways. |
| F3 | **P2 · Command registry.** | CLAUDE.md: "Do NOT run these directly with `./target/debug/deno test`". The task runner defines `test-unit`, `test-spec` and others. | `.harna/commands.toml`: name → command → what it proves → local or CI. Onboarding tells agents the right test command for the container they touch, and F1 checks the docs against it. |
| F4 | **P2 · CI routing from the manifest.** | CI skips runs on `docs_only` and `skip_deno_core_test`, both hand-written conditions. | Parity already computes the affected containers. The generated CI can run per affected container and skip docs-only changes. This extends 0.3.41's CI economy. |

## G. Language boundary (feeds the 0.4.0 language-plugin milestone)

| # | Gap | Evidence | Extend |
|---|-----|----------|--------|
| G1 | **P2 · Cross-language surface inventory.** | 511k JS/TS lines are invisible to harna. Ops are declared in Rust (`#[op2]`, `extension! { ops = [...] }`) and consumed in JS (`} = core.ops;`). No op-name ↔ binding check exists. | Start the language frontier with the boundary, not a full parser. Inventory exported names on the Rust side and consumed names on the other side, then flag dangling and unused ops. C2 count pins apply. |

## Organization patterns worth teaching (no gap, but harna's model should name them)

- **One crate per capability** (`ext/fs`, `ext/net`, …). A container is a crate. The dir name
  drops the package prefix, so dir ↔ package mapping is data (A1).
- **Composition owns injection.** The runtime puts backend trait objects (`FileSystemRc`) into
  state, and capabilities never pick their own backend. harna roles cover this (gateway, base,
  orchestration); `place` should suggest it.
- **Tests mostly inline** (307 files with `#[cfg(test)]`), with spec suites as data. Both are
  legitimate; harna should not push one style (E5).
- **Very large files survive** (`runtime/permissions/lib.rs`: 11,756 lines). The hotspot and
  granularity advisories are right to name them; A6 calibration keeps that from becoming noise.

## Suggested order

1. **0.3.44, seeing correctly:** A1, A2, A3, A6, C1. Without these, harna on a big repo is
   wrong (A1–A3) or unadoptable (A6, C1).
2. **0.3.45, boundaries as capabilities:** B1–B5, D1.
3. **0.3.46, hygiene and agent docs:** F1, F3, F2, E3, E4, E1, E2, D2, C2.
4. **0.4.0:** G1 with E5, A4, A5, F4.
