# Bounded queries; one-level index stays

Decision 2026-10-17, shipping in 0.3.16: the Phase D bounded reads. Store grows in place (no new component): for_each_shard streams modules in digest order, one shard resident at a time, stamps riding every visit, visitor early-stop; load_index and load_shard serve consumers that never need modules in full. The legacy monolith joins the stream as a single pass (bilingual, like load_digest); a map-less repo reads Ok(false) and the caller owns the scan refusal. Consumers: whereis streams up to three passes (exact, case rescue, substring rescue capped at the render limit) keeping matching declarations only; dependents resolves its target from the index path list — the 0.3.15 enabler, no shard parsed for resolution — then streams shards twice for ring 1 and ring 2, holding edges only; metrics::build_store streams into the graph projection (path + deps, signatures and inventory never materialize) and keeps the one shared edge resolution via build; onboarding renders the overview from counts plus the leading ten modules, byte-identical to the whole-map era (render_overview delegates to the same render_overview_from). THE TWO-LEVEL INDEX DECISION (flagged first in 0.3.15): declined. The index's compact records are linear in modules (a path plus a hash each); bounded queries stream shards, so the index parse is the only whole-list read and it sits orders of magnitude below the map. A two-level index pays off only when the index itself becomes the bottleneck at millions of modules — revisit alongside 0.3.17's body-hash reuse, whose per-module index reads are the first consumer that could want per-shard sub-indexes. No mechanism was built for a need that does not exist yet. Honest notes: the resident set of metrics is the import graph itself (fan/pressure measurement is OF the graph — an honest bounded, not an O(1) footprint); whereis spends IO (re-streaming) in place of memory; the remaining whole-map consumers (status, place, plan, score, hotspots, diff/validate) stay as-is for 0.3.17's one-scan-many-consumers fast path. Dogfood: 191/191 tests (6 new pin the stream order, stamps, early-stop, bilingual legacy pass, mapless refusal, and the renderer identity); validate 0 error.
