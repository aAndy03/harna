# TypeScript edges are file edges, never Rust deps

0.6.0. TS imports could be encoded like Rust deps (crate + stem) to reuse resolve_dep, or as their own kind. TS resolves to files, not crates/modules, and packages are not workspace crates; forcing them through the Rust resolver would give wrong homes (crate_of's src/ convention) and phantom edges. Chosen: deps 'file:<repo path>' (resolved), 'file?:<spec>' (unresolved), 'npm:<pkg>' (external); file_edge() is the one place that reads them, dep_reaches/dep_points_at/metrics short-circuit on it, and the TS boundary check works on paths and containers directly. TS modules carry no crate_dir and skip the orphan pass (a TS file is reached by imports, not a crate target). Bridges (0.6.1) will add 'bridge:<rust file>' edges read by the same function.
