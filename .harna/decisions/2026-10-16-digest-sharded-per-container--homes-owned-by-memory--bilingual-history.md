# Digest sharded per container; homes owned by memory; bilingual history

Decision 2026-10-16, shipping in 0.3.15: digest sharding plus compaction. The map persists as .harna/digest/index.json (stamps plus compact path-plus-hash records per module) plus one shard per container with its modules in full, digest order preserved inside each shard and across the index so a sharded round-trip is module-for-module identical. Loading is shards-first with legacy digest.json fallback; saving writes shards and removes the monolith (one truth, never two); digest_at_ref probes for the index at the ref and falls back to the monolith, so history stays bilingual - verified against real history (diff HEAD read the committed monolith). module_homes, module_layers and ModuleHome moved to schema/manifest (they join two memory types) so Store can shard without reaching into search; digest and validate keep working through re-exports with zero caller changes. save_digest now takes the manifest (7 call sites updated: 2 prod scan paths, 5 tests). Per-module bytes are unchanged by design (wire stability beats micro-trimming; skip_serializing_if already omits empties) - the 0.3.15 win is structural: parse units shrink from the whole map to one container, and the index compact records are the substrate 0.3.16 bounded reads and 0.3.17 body-hash reuse build on. Old tool versions cannot read new repos (forward migration, noted).
