# Fast paths: one scan, many consumers; parallel scan; body-hash reuse

Decision 2026-10-17, shipping in 0.3.17: the Phase D fast paths. ONE SCAN, MANY CONSUMERS: score::full (the harna metrics machine shape) reads the committed map once and passes it down — the whole-map era stacked four reads (metrics streamed it, score loaded it, the CLI loaded it again, hotspots joined the third). The shared core is score::build_with (coverage, parity debts, freshness from inputs a caller already holds); the plain metrics path renders the same three sections from the same one read. PARALLEL SCAN: build_incremental fans the per-file work (hash-verified reuse or a fresh parse) over one thread per chunk of the file list (std::thread::scope, no new dependency; 16-files-per-thread floor keeps small repos on the calling thread); the final path sort makes the result identical whichever way the chunks land. DIFF REUSES THE MAP (CLI and MCP): the working-tree scan was a full rescan; now it is the same incremental build harna scan runs — hash-verified reuse is content-addressed, so the diff is identical, the parsing a fraction. INCREMENTAL VALIDATE (body-hash reuse): pattern-rule name extraction reuses the map's inventory when a file's live body hash equals the recorded one (extractor-gated like the scan's reuse) — the inventory catalogs exactly what declared_names derives (the same filtered parse loop), so a matching hash means the catalog IS the parse; validate's map read joins the one-scan discipline (one load per run, moved above the file loop it feeds). THE TWO-LEVEL INDEX CHECKPOINT (deferred 0.3.15, declined 0.3.16): answered — one level is enough, now with evidence. The reuse consumer (validate) consumes whole modules' inventories from the one map read its other checks already needed, and the scan's reuse reads the previous map wholesale; the hash lookups ride reads that exist anyway, so a second index level would index a lookup nobody performs standalone. The compact records keep their job as the diffability/substrate layer, not a query path. Honest notes: the parallel scan has no thread pool and nothing to tune; validate's reuse skips the parse, never the read (a violations cache keyed by hash would need persisted state — nobody's ask yet); standalone score::build is one read by definition, nothing to share. Dogfood: 194/194 tests (3 new: parallel-scan equivalence over 24 files, hash-verified name reuse, full-report consistency), validate 0 error, doctor 11 ok, metrics output unchanged.
