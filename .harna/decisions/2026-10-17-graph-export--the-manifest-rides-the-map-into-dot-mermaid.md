# Graph export: the manifest rides the map into DOT/Mermaid

Decision 2026-10-17, shipping in 0.3.19 (the 0.3.9 deferral collected): harna graph (CLI, --format dot|mermaid) + harna_graph (MCP tool 24) export the dependency graph. DATA DOCTRINE: nodes are map modules, edges are metrics::resolved_edges - the SAME resolution the metrics ledger and rank caps already use, made pub deliberately (one shared resolution, no second opinion between the ledger and the picture of it). CLUSTERS ARE THE MANIFEST'S: build() emits nodes manifest-first (each container's modules in map order, unhomed modules last - adoption debt visibly at the bottom), so the renderers' first-appearance grouping IS manifest order; DOT pins vertical layer ranks with a per-layer anchor chained by invisible weight-100 edges (clusters alone only suggest order), Mermaid nests subgraphs (no rank pinning exists there - best-effort by renderer, said plainly). THE FIX: while building the graph fixture, a pre-existing bug surfaced - cross-crate edges silently dropped everywhere (dep targets carried the import-site spelling harna_core:: while the crate-to-dir host lookup keys on package names harna-core); fixed in resolve_dep (the target now carries the matched workspace package name) so every consumer benefits; dogfood metrics went from lopsided to 165 edges with cli/mcp finally reporting their real outbound fan (-23/-20) - boundary pressure is true now, exactly the ledger the graph depicts. SCOPE EXCLUSIONS: stdout export only (not a committed view, no staleness gate, no --out - the interface layers gain no filesystem writer; redirect stdout); module-grain edges (the map's deps are module-grain; symbol-level needs a different substrate, no ask). 202/202 tests (3 new over the graph: homes+edges one resolution, DOT order+anchors, Mermaid positional ids).
