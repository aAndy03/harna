# 0.4.2: profiles are data folders; gpui-kit's guide shapes the first one

Profiles are folders of the same registers a project already has (manifest, rules, qualities, terms, commands, non-goals) plus profile.toml; no new language, no code generation. Shipped profiles are embedded from crates/harna-core/profiles/ so they ship with the crate; user profiles live in ~/.harna/profiles or any folder. The first profile follows the gpui-kit Coding Guides literally: organize by capability (feature crates in an isolated layer), shell composes, shared stays headless, platform behind seams. Its first draft put a crate:gpui-kit gateway on two containers, which would have made every future feature crate a violation; the headless guarantee is instead a crate-conformity rule with the new negation (!toml:dependencies.gpui-kit) on the shared and platform crates. Isolation is a generic layer property, not gpui-specific: it is also the user's original 'engines never import each other sideways'.
