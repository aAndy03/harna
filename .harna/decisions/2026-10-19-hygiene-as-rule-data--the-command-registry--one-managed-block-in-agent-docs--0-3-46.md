# Hygiene as rule data, the command registry, one managed block in agent docs (0.3.46)

From the deno study. Each lint.js-style check is a bindable rule (scope/values/pattern/limit) in a new validate/hygiene group, so a repo states its hygiene instead of scripting it. The command registry is data; doc-claims checks only repo-local runners (./x) against it — external tools (cargo, harna) have subcommands nobody registers (dogfood caught that design flaw on harna's own AGENTS.md). Agent instruction files get a marker-delimited block rendered from .harna/ (rules, commands, layers); prose outside it stays the humans' and files without markers are never touched (rejected: owning the whole file — teams write real guidance there). generated never runs generators (no-code-execution stands): it exempts outputs from budgets and names hand edits from git status. file-header accepts the header anywhere in the leading comment block (deno's checker allows a preamble). Performance: HARNA_TIMINGS showed per-module git rev-list was 32s of 74s; churn is one git log pass now. Found: harna move misses root-relative paths in a binary crate's main.rs and grouped imports — logged for 0.3.47.
