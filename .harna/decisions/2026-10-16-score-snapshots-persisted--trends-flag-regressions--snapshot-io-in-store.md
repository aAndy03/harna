# Score snapshots persisted; trends flag regressions; snapshot IO in Store

Decision 2026-10-16, shipping in 0.3.13: metric snapshots + trends. Scores persist as timestamp-slugged TOML under .harna/scores (git-tracked, committed as the release baseline); same-stamp collisions take _N (dash would sort before the .toml dot and invert chronological order - caught by test). Trends print deltas between consecutive recordings with the regression flag at -5; the status line carries drift vs the last recording (= last, +/-N, REGRESSION flag). Missing scores dir is empty, not error; corrupt files fail loudly. Dogfood caught a real layering slip: score.rs wrote snapshots with std::fs directly and gateway-ownership fired - persistence moved into Store.save_score_snapshot/score_snapshot_names/read_score_snapshot (the fs:write gateway) instead of widening the briefing declaration. Retention and pruning wait for 0.3.18 archive & compaction (snapshots are ~500 bytes each; unbounded growth is a known, bounded cost).
