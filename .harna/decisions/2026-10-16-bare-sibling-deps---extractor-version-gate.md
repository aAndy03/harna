# bare sibling deps + extractor_version gate

Dogfooding 0.3.2 whereis exposed a long-lived graph blind spot: unrooted sibling calls (rule_bindings::Bindings from validate/mod.rs) never became edges, so parity/dependents/whereis stayed silent about them. Decision: the extractor records them as self::-relative ids (legal only in expression position; use lines exempt because bare sibling use cannot compile in Rust 2018+), declared_mods feeds both scan and boundary so map and validate cannot disagree. Because extraction SEMANTICS changed, incremental reuse had to move from hash-only to hash+extractor verification: Digest.extractor_version stamps the map (EXTRACTOR_VERSION=2); older maps rebuild in full on first scan — file hashes cannot certify that the extractor stopped being blind. Known limitation, documented: string literals containing 'modname::' can produce phantom sibling edges (same pre-existing caveat as crate:: strings).
