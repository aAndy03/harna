# Sub-containers are folders: nested paths and folder budgets, not a new manifest type

0.3.39 set out to add sub-containers to the manifest. The manifest already expresses both kinds of nesting: a boundary inside a layer is a second container whose path nests under another (module_homes resolves the longest prefix), and a plain grouping of related files is a folder of components. What was missing was pressure and safe tooling, not a data type: nothing limited files per folder, file names carried the grouping instead (8 *_data.rs in schema/), and moving files by hand broke four kinds of links. So 0.3.39 adds (1) folder-size and name-cluster checks, rule-bound and enforced on harna itself as errors (folder-budget: 8 files per folder; no-name-clusters), (2) harna move, which relinks manifest paths, tests, rule scopes, mod declarations and use-paths through typed models and a literal-aware rewrite, and (3) restructures harna with it: schema/{model,registers,journal,store}, validate/{boundaries,coherence,sizing,content}, generation/{structure,views}, composition/{briefing,gates,hooks}, cli commands/registers. A true nested Container type was declined for now: it would add boundary semantics (sideways-import rules between sibling folders) that harna's own folders do not want, across ~25 consumers. Revisit if a codebase needs per-folder roles or gateways.
