# Profiles: init --from copies another repo's conventions, never its history

Decision 2026-10-17, shipping in 0.3.21: harna init --from <path> drafts a fresh .harna/ from another repository - the Phase E collaboration continuation. WHAT COPIES: rules.toml + manifest.toml ONLY, verbatim byte copy (a profile is a starting point to prune, not a template to re-render - the bytes stay readable data; load-verified through the loaders, not re-rendered). SOURCE SHAPE: the path may be the repo root (reads .harna/) or a .harna/ directory itself; a missing piece leaves the starter in place (ProfileApplied names what landed). SAFETY ORDER: source pieces parse BEFORE any overwrite - broken profile refused, starter rules intact (a broken profile must never poison .harna/). THE INTERPLAYS ARE NAMED IN THE INIT REPORT: the copied manifest's paths point at the OTHER tree - prune and re-point (edit or harna scaffold); copied rules' scopes that miss this tree simply apply nowhere (scope filtering already data-driven - nothing special-cased). ADOPT COEXISTENCE: after a profiled init, harna adopt refuses the non-empty manifest - the skeleton is explicitly full; scaffold and direct edits continue. NEVER COPIES: decisions, scores, parity, digest - a profile carries the other repo's conventions, not its history. NO MCP TOOL: init is bootstrap, human-owned; agents arrive at initialized repos (no ask). NO PROFILE FORMAT: the profile IS another .harna/'s data - no second representation to keep in sync. Dogfood: donor copy verified verbatim through rules list + manifest load; adopt refusal surfaced as designed (temp dirs created then deleted - front hygiene). 207/207 tests (2 new: verbatim via loaders, missing-pieces + refuse-before-overwrite), validate 0 error (7 info tolerated), doctor 11 ok, parity harna-0-3-21 19/19 ack+resolved (1 real: apply_profile+ProfileApplied; 18 innocent store.rs import fan).
