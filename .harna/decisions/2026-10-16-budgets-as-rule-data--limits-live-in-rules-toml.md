# budgets as rule data (limits live in rules.toml)

0.3.7 adds container-size and fan-out-cap with thresholds as data: Rule.limit (additive Option<u32>), strictest-applicable-wins (min), scope-constrained applicability, reg default Info so budgets start as guidance and are promoted per rule via severity. Fan-out counts DISTINCT HOSTED targets: a dep id with a symbol tail maps to its hosting module via longest-stem over the digest index, so two calls into one module are one import; unresolved stems stay visible with their own count instead of being silently dropped. No rule/no limit = no gate: budgets adopt per scope in the repo's own rules.toml; harna itself has not declared budgets yet (structural budget quoted in the granularity advisory stays advisory). CLI --limit / MCP limit validated to bind only budget checks.
