# plugins are vendored packs whose rules join at load time

0.5.0. A plugin (framework knowledge: gpui-kit 0.8.0) could (a) be copied into rules.toml/terms.toml on install, (b) stay referenced from the harna binary or ~/.harna, or (c) be vendored as its own folder under .harna/plugins/<name>/ and merged at load time. (a) mixes framework rules with the project's, so an upgrade cannot tell which to replace and edits would be lost; (b) makes the repo's enforcement depend on what is installed on each machine (offline, reproducibility, review all break). Chose (c): the pack is reviewable data in the repo, versioned with the code; load_effective_rules namespaces its rules <plugin>/<id> (no collisions, origin says which pack); edits to rules.toml never touch it; re-adding upgrades in place. Admission against the check registry happens at the CLI/MCP edge because construction may not import integrity. The doctor compares mirrors with Cargo.lock on the release line (0.x minor) so a framework upgrade surfaces its stale conventions. The rust-gpui-desktop profile keeps architecture only and installs the plugin (tools-not-prescriptions).
