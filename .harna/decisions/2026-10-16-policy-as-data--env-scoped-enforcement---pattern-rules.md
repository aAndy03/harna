# policy as data: env-scoped enforcement + pattern rules

0.3.3 makes the rule set executable policy per environment and lint-as-data. Env scoping: validate runs declare an env (CLI --env, MCP env); Bindings/overrides/patterns filter by matches_env so a dev-tagged rule enforces only in dev runs — env-less rules always enforce. Pattern rules: Rule.pattern (regex crate, first new dependency since 0.3.0 — justified because naming conventions need honest regex, not glob approximations) matched over file paths AND declared names via declared_names(), deliberately inventory-aligned so the check polices exactly the names the map catalogs. Pattern implies binding to the `pattern` check (registry id 11, Info default); an explicit conflicting `check` warns (coherence), a regex compile failure warns and the run continues (hand-edited data must be visible, never crash enforcement). Known limitation documented: pattern matching is content-name/path based, not position based — a violation cannot name a line for pattern hits (line 0), consistent with parity/granularity advisories.
