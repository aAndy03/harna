# declared surface: provides in the manifest, gated on the live graph

0.3.4 adds encapsulation: Container/Component gain `provides` (additive serde default). The `declared-surface` check (12th registry id, Error) evaluates cross-container imports on the live graph: when the target container declares a non-empty provides (its own plus components'), any named symbol not on it is a violation; separately, truly private (vis-priv, non-impl-kind) symbols never cross containers, provides or not — the digest inventory is the witness, so no map degrades to declared-side-only. Adoption is opt-in per container: undeclared containers only owe the private rule. Edge semantics pinned: whole-module imports (dep stem == a module stem) are exempt — no symbol is named; brace-group imports collapse to their head module (extractor behavior, documented); innermost host container wins for stem boundary-matching; impl blocks are excluded from the private set because Item::parse stamps `impl X` as priv and the name collides with the type (a real false positive found validating harna itself: 26 phantom errors before the exclusion). Dogfood: harna's own containers declare nothing yet, so only the impl-fix was needed to stay honest.
