# Archive & compaction: filed state leaves the live surface

Decision 2026-10-17, shipping in 0.3.18: .harna/ stays lean forever. harna archive (CLI) + harna_archive (MCP, tool 23) file closed state into .harna/archive/<kind>/ - closed parity events, superseded decisions, score snapshots past retention. The move is a same-volume rename: the bytes never change, the git-tracked ledger stays greppable - 'compress' is of the live surface, not the bytes (gzip would save kilobytes and cost readability; said plainly). POLICY PER LEDGER: parity - an event with no open targets owes nothing and files off (archive/parity/); open events stay live no matter how old, an open target is a promise, not history. Decisions - the visibly-dead tail files off whole: whoever supersedes a decision is newer than it, so a dead decision's own supersedes target is dead too, meaning the live log keeps exactly the current heads and every live pointer resolves into live-or-archive; the decision-chain check was extended to resolve pointers into the archive set (a filed decision is history, NOT a ghost - a pointer at something neither live nor filed is still an Error). Scores - the 0.3.14 retention deferral collected: SNAPSHOT_RETENTION=12 (a year of bursts is the trend window the grade reasons about), the newest 12 stay live, older file off to archive/scores, --keep overrides, trends read the live window. The dogfood run filed 22 closed parity events and 2 superseded roadmap decisions; status now reports 'parity: 0 events' instead of 22 closed ones. Honest notes: archived decisions leave harna decisions and the chain walk (live views only) - no --archived viewer was built, no ask yet, git history serves; the archive dir gets no doctor check (doctor checks data health, not filing). 199/199 tests (5 new: closed-files-open-stays, dead-tail-moves-whole with archive resolution, retention window, archive_file rename bytes, idempotence).
